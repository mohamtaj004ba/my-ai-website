# Bounded implementation tasks

The existing five-stage implementation workflow now accepts reviewed server-owned task descriptors in addition to historical Starter contracts. It is not a generic editor, command runner, paid authorization or publication service.

## Repeatable delivery

1. Reproduce a real product defect against current source. Preserve the failing evidence before a correction.
2. Freeze the approved source manifest, full target preimage and exact evidence excerpts in the authenticated task asset. Define a unique objective, one file/anchor, closed replacement grammar, bounded bytes, complete criteria and explicit test-profile status. Update the asset pin only through reviewed source development. Never accept definitions or regexes from model output or owner request bodies.
3. Exercise the existing Chief → Specialist → QA → Auditor → Chief path. The model schema receives exact source/binding/descriptor metadata. Backend validation checks the entire descriptor, preimage, evidence and permitted replacement before the existing data-only child applies it to a disposable copy and destroys it.
4. Keep current-source admission separate from historical replay. Resolved or changed sources reject fresh assignments. Frozen receipts and explicitly offline historical fixtures remain readable; they confer no fresh authority.
5. Review actual patch integrity, impact, coverage and unresolved findings. A completed workflow may correctly end with Auditor rejection. Technical roles are not independent human acceptance.
6. Work may implement and publish an independently reviewed correction through the authorized feature Preview process. Record author attribution, exact source fingerprint, CI/security/Redis results and actual Browser archive. Internal agents retain no repository or deployment permissions.

The notification-control task demonstrated all five stages with explicitly offline reasoning and actual disposable-copy application against its then-current source. Work authored the final product correction and behavioral tests. It is not a new live model-generated fix. The original genuine Starter agent patch remains separately attributed and unchanged.

## Execution and paid boundaries

Each registered task currently has testProfile:null. It cannot reuse the qualified historical Starter source-test program, whose exact source hashes remain enforced. General generated-code execution requires separate qualified isolation and reviewed authorization. Merely registering a task does not add it to any paid trial policy or revive a consumed approval. Existing owner/release/task/spending/cancellation controls continue to apply.

New task preparation uses the current lock; historical data-only copy selection is limited to authenticated frozen assets and preserves authorize-before/after, cancellation and actual-current-file integrity checks. No network, dependencies, source execution or real repository modification occurs in that child.
