Both were engineering contract defects. Large regression counts covered security/state behavior but were not evidence of model-interface completeness. The native five-stage HTTP mock read org.readWorkflow and passed its internal DTO into validator-aligned fixtures. This disclosed constraints that a real model did not receive. Happy-path tests and security review correctly established fail-closed behavior while missing preventable request drift. Adjudication had similar undisclosed limits. The old final-report schema allowed unrestricted prose, so it could misreport acceptance even though it could not change backend acceptance. Specialist input also omitted capture geometry by reading an undefined DTO field; backend geometry checks remained active, but model-input coverage was incomplete.

## Preventative controls

lib/agent-operations-contracts.js is the authoritative structural contract for all five new organization stages: schemas, exact model-facing instructions, strict response format, model/reasoning/output/cache/tier envelope, and structural validation. Backend validators reuse it rather than maintain parallel structural bounds. Evidence binding, hashes, all-image coverage, unique IDs, ordered boxes, exact claim/atom correspondence, relevant same-image references, uncertainty thresholds, geometry conflicts, stale state, cancellation, permissions and independent acceptance remain separate backend semantic checks. JSON Schema cannot establish truth or every cross-field invariant.

Chief intent remains action/agent/reason only. Revisions, task IDs and execution/concurrency bindings are backend-owned. Final Chief reporting is deliberately bounded to one of two canonical labels, selected from authoritative acceptedWork. Both the native receipt parser and atomic backend finish reject a false-success label. It is a status report, not unrestricted narrative summarization.

organization-contracts-v1 release identity fingerprints all five schemas/instructions, relevant constants and validator functions, and14 whole selected boundary-module sources with LF normalization. This includes captured helpers, policy/project/model/token/time/spending values, not merely a schema snapshot. The checked-in lock must match. New task DTOs bind version/hash; owner approvals must bind the same release; provider and broker dispatch recheck it before credentials/transport. Exact request schema/instructions/envelope checks run before dispatch. Legacy approvals cannot initialize the new path. No model receives authority to update this gate, lock, approval, policy or budget.

Run `npm run preflight:agentops` before future pilot preparation. It checks the release and executes the contract/security/concurrency/full mocked-path suite with provider fetch disabled and credential variables stripped. CI runs this as a mandatory, non-optional step. A lock update is a reviewed source change, not an automatic repair: rerun the preflight/full suite, independent review, exact-source CI/CodeQL/hosted checks, then bind a fresh owner approval only after separate paid authorization. The release hash detects drift; it is not a cryptographic proof that an operator ran tests or that visual judgments are true. Existing read-only scope, budgets, no retry/recurrence and paid=false defaults remain intact.

## Tests that would have prevented both pilots

Pinned sanitized recorded-response fixtures preserve raw returned arguments/output text, usage, request IDs and provenance hashes. Historical reports and screenshots are not rewritten. Tests show the Chief's2 is valid under its old permissive schema but the old authority-bearing request fails the new pre-dispatch gate, before fetch. Tests show the29-fact observation is valid under its old schema but both its schema and omitted instructions fail the new pre-dispatch gate; the original response remains rejected without normalization, truncation, ID rewriting or silent substitution. Successful real Chief-v2 and specialist outputs also replay against the shared structural contracts. These latter replays verify response contracts, not a new live execution or renewed authority for historical responses.

Boundary and adversarial tests use independently fixed examples: exact/beyond count and text limits, pixels/reversed/zero-area boxes, missing-image coverage, duplicate/invalid IDs, extra authority fields, wrong/missing claim atoms, borrowed/unrelated observations, unsupported suitability, low confidence, false approvals, stale/cancelled/replayed/concurrent tasks, envelope drift and false final success. Both semantic failures and unchanged pending reservations are asserted. Mutation tests remove schema constraints or change instructions/envelope/helpers and require failure before transport.

The native HTTP provider mock now accepts only the outbound request body. It never reads a workflow DTO, store, capability, hidden expected revision or acceptance oracle. It derives claim/observation IDs and final status only from model-visible input. A separate non-model acceptance callback retains its independent role. Full five-stage native mocked paths cover accepted/rejected work; additional paths block invalid adjudication references and false-success final reporting without further advancement. Internal synthetic backend fixtures remain component tests, explicitly separate from model-contract and live proof.
