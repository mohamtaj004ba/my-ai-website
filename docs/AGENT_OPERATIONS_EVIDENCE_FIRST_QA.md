# Evidence-first visual QA investigation and proposed methodology

October 11, 2026. Design and offline investigation only. Paid execution remains disabled; no provider request, activation, deployment or historical rewrite. The accepted technical pilot remains a failed substantive quality evaluation. This document does not authorize another pilot or implement a replacement hosted mode.

## What the failure establishes

The original QA request used the fixed GPT-4.1 snapshot, native Responses path, four original PNGs at high detail and correct source/hash binding. It completed with HTTP 200, 4371 input/871 output tokens. The four `accept` verdicts and the separate failed acceptance assessment are retained unchanged. An image transport failure, missing evidence or wrong source is not supported by the retained evidence. It is not possible to inspect the model's internal attention or reconstruct why it chose those judgments.

The complete specialist conclusions were supplied in the same initial user input as the images. The reviewer was independent in execution identity, but its observation was not blind to the claims. It repeated the same incorrect price-overlap location and accepted domain-suitability inferences. **Text anchoring/confirmation bias is a plausible mechanism, not a proven internal cause.** High detail did not guarantee correct spatial interpretation. OpenAI documents small-text, spatial-localization and accuracy limitations for vision models. [Vision limitations](https://developers.openai.com/api/docs/guides/images-vision).

There is also a demonstrated acceptance-design weakness: `validVerdict` enforces shape, four codes, allowed image hashes, references, sufficiency flags and consistent overall decisions. It cannot establish that a cited region contains the asserted defect. The model can declare sufficient evidence, leave unsupportedClaims empty and pass syntactic validation while being wrong. Adding more forceful agreement/rejection wording alone is not a verified correction.

All four original findings were rejectable as written: two contradicted overlap claims and two insufficiently established suitability conclusions. The historical review approved 4/4, including 2/2 contradicted and 2/2 insufficient claims. This is a single correlated bundle, not a population error rate for GPT-4.1. There were no supported positive controls, so false rejection cannot be estimated. No numeric support probabilities were retained, so Brier score/calibration cannot be recovered from `evidenceSufficient=true`.

## Proposed sequence: observe first, then assess claims

Use separate request contexts and durable records. Putting “observe first” at the start of a prompt that also contains the findings does **not** blind the observer. A future two-phase model path requires separate implementation and execution authorization; the consumed one-call approval cannot be reused or expanded.

1. **Trusted evidence admission.** Parent verifies original task/result/file hashes and dimensions. Keep original PNG bytes unchanged. Assign opaque image IDs I1–I4; retain original filename/task mapping privately in the audit binding. Do not send finding codes, filenames such as legal/pricing, specialist notes, previous QA verdicts, owner corrections or evaluator labels to the observer. Visible page content itself may convey industry context; that unavoidable context must be distinguished from evidence of suitability. New crops/OCR, if ever authorized, are derivative artifacts with explicit transforms/source hashes; no silent replacement or enlargement pretending to recover missing detail.
2. **Blind observation, fresh context.** Send only the images, opaque IDs and a neutral rubric. Record objects, exact text only when readable, spatial relations, normalized regions and unreadable/ambiguous areas. Separate direct observations from hypotheses; do not diagnose industry fitness, security, behavior or causes. An observer example is “an orange strip and a heading share a region,” not a predetermined defect answer. Do not reveal the overlap-location correction. The actual observation output must be evaluated, not assumed correct because it precedes claims.
3. **Freeze observations before disclosure.** Parent durably stores task ID, image-set hash, prompt/model version, structured observations, observation hash and sequence/time. Observation results are immutable and independently addressable. A hash alone is not authorization: the broker must bind the approved receipt to the task and forbid replacement/recomputation after claim disclosure. Require cancellation/lease/budget checks before the second stage; no automatic repair request.
4. **Adjudicate atomic claims, separate fresh context.** Send the locked observations, original images and each original finding verbatim. A curator-controlled manifest decomposes material assertions, with exact source spans and full-text hash so no unsupported clause can disappear. Proposed correction text is a hypothesis, not evidence that a defect exists. Require a separate result for every atom: supported / contradicted / insufficient; image ID/hash/region, observation ID, specific reason, limitations and numeric `pSupported` for *support in this supplied evidence*, not real-world truth. No owner correction, gold label or prior verdict is included. If the observer missed a relevant region, mark a discrepancy/insufficiency for acceptance review; do not rewrite the frozen observation or silently launch another observer.
5. **Aggregate conservatively.** Accept an original finding only if ALL material assertions are supported. Contradicted or insufficient atoms reject the finding as written; preserve any narrower supported observation separately. Reject missing atoms, unrelated references, altered evidence, wrong viewport and source disagreement. A claim about confidential-record handling needs evidence of that capability; a screenshot's presence on a Legal page is insufficient. A static image cannot demonstrate keyboard behavior, persistence, security or protected-data suitability.
6. **Independent acceptance.** A deterministic scorer compares outputs against separately curated labels and geometry where applicable. Human evidence adjudication owns ambiguous suitability/readability labels; the candidate model cannot grade itself. A valid JSON response and durable `verified` execution remain separate from substantive acceptance. Correct schema/coordinates do not establish correct visual meaning. Contradictory deterministic evidence blocks automatic acceptance. Purely subjective design suitability is advisory and requires owner review.

Future records: immutable `qaObservation`, separate `qaClaimVerdicts`, then separate `qaAcceptance` with rubric/label/geometry versions. Link to the original task and each other; do not edit `results.inspect`, the failed `qaVerdict` or the failed acceptance record. Keep existing dedicated credentials, Preview-only scope, task permissions, lease/fencing, cancellation, no replay/recurrence/retry, sanitized diagnostics and conservative reservations. No code-writing or repository tool is granted to either reviewer.

For future authorized capture, collect a geometry sidecar in the same browser state/frame as each PNG: exact deployment/source, screenshot SHA, viewport/DPR/scroll/zoom, browser version, fonts, timestamp, unique element selectors and text, element boxes, `Range.getClientRects()` for text, computed styles, clipping ancestors, transforms and stacking/pseudo-elements. Freeze animation and wait for fonts plus stable measurements; if layout moves between measurements/capture, mark the pairing invalid rather than asserting a defect. Proposed selectors are curator-controlled: `#pricing article.featured .badge`, its direct `p` heading, and `h3` price; missing/duplicate nodes fail to unknown.

For rectangles A and B, intersection is `max(0,min(right)-max(left)) × max(0,min(bottom)-max(top))`. Report signed vertical gap and overlap area/ratios, with a documented 1px candidate tolerance. Test badge-heading and badge-price independently; do not call both “text.” Rectangles are candidate intersections, not proof of painted glyph occlusion: padding, line boxes, transparency, clipping, transforms, stacking and deliberate overlays can produce false positives. Use text ranges, visible-region/pixel review and stable multi-frame samples before classifying occlusion. DOM text can be hidden or misleading, so it cannot establish business suitability. [Playwright bounding boxes](https://playwright.dev/docs/api/class-locator#locator-bounding-box), [DOM text ranges](https://developer.mozilla.org/en-US/docs/Web/API/Range/getClientRects).

## Small adversarial evaluation and acceptance criteria

`docs/qa-evaluation/seed-cases.json` contains 16 individually identified cases bound to the four original image hashes: 6 directly supported narrow claims, 4 contradicted locations/prices, 5 insufficient claims and 1 substituted-hash integrity case. It includes all four exact original finding texts, paired correct/incorrect claims on the same image, already tiny mobile text, unproven industry/security claims and interaction behavior that static images cannot prove. Original images are not altered or relabelled. Claim holdout is distinct from development claims, but uses the same images and is not a generalization holdout.

Labels are a **curated seed**, informed by actual images and prior owner acceptance. Before a paid comparison, obtain two independent human annotations with source regions/reasons; disagreements become insufficient or are adjudicated, never force-labelled for a preferred model. Keep labels and expected corrections outside both request contexts. Add genuinely unseen, independently rendered image bundles before claiming broader reliability. Future counterfactual fixtures should cover actual price occlusion, clean no-overlap, heading-only overlap, clipping, transforms, hidden elements and near-tolerance boundaries; they are distinct test artifacts, not edited historical PNGs.

Track separately:

- False approvals: accept on contradicted OR insufficient evidence / all rejectable cases. Also report contradicted-only false approvals and insufficient-claim approvals separately.
- False rejections: reject on supported evidence / all supported cases. Include acceptance precision and supported-case coverage; “reject everything” cannot pass.
- Uncertainty: insufficient cases correctly rejected *as insufficient*, not falsely stated contradicted; support probability Brier score and three-bin ECE, alongside bin counts, reliability plot and confidence/coverage curves. Probability concerns evidentiary support, not unknown world truth. Confidence wording alone is not calibrated probability.
- Integrity and attribution: missing/mismatched images rejected before dispatch; correct source regions/viewport/observation IDs for every atom; no omission of material clauses. Check factual observation correctness separately from final claim decisions.
- Ordering robustness: deterministic randomized claim/image order and paraphrases, without changing truth. Treat repeat views/paraphrases as correlated. Analyse paired errors on the same source bundle; use bundle-level intervals/resampling when there are enough independent bundles. Do not cherry-pick agreeable runs or repair failures with paid retries.

Initial **smoke gates**, not a release proof: 0 false approvals across the 9 rejectable seed cases; at most 1 false rejection among 6 supported cases; all 5 insufficient cases explicitly rejected as insufficient; integrity case rejected before model dispatch; complete atom coverage/correct references; geometry distinguishes heading versus price at both widths. With numeric probabilities, target Brier ≤0.15 and ECE ≤0.10, always reporting bins/counts and sample limitations. These thresholds are predeclared proposals, not measured candidate results.

Even 0/9 false approvals would have an optimistic one-sided 95% binomial upper bound about 28.3% **if** independent; these cases are correlated, so that bound is illustrative only. Expand to at least 60 distinct negative cases across independently sampled bundles before a low-error claim; 0/60 independent failures has a one-sided upper bound about 4.9%. Require all original critical failures rejected, no degradation in positive controls, and confidence intervals before claiming a model is measurably better. An underpowered or tied result remains inconclusive.

Offline scaffold `../../agentops-tools/qa-methodology/evaluation.cjs` creates the seed/manifest and tests packet blinding, immutable observation linkage, hash/reference rejection and scoring. It contains no provider client/endpoint/credential loader; tests forbid fetch. Thirteen tests passed. Agree-all scores 9 false approvals/5 insufficient approvals; reject-all scores 6 false rejections. A synthetic correct classifier validates scoring only. This prototype does not implement the full atomic-claim hosted workflow or prove visual competence. Measured improved-GPT-4.1 and alternative-model accuracy remain **null**. [Evaluation guidance](https://developers.openai.com/api/docs/guides/evaluation-best-practices).
