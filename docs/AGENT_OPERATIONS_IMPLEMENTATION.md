# Agent Operations implementation checkpoint

Phase 1 development uses real durable control logic and mock model execution. Paid website acceptance remains pending. The initial architecture record is in AGENT_OPERATIONS_PHASE1.md; pilot terms are in AGENT_OPERATIONS_PILOT.md.

## Implemented

- `lib/agent-operations-store.js`: bounded durable ledger, task/idempotency creation, atomic compare-and-set, leases/fencing, events, distinct chief/inspect/review/report stages, bounded rework, cancellation, uncertainty-preserving recovery and task/day/month cost ceilings.
- Redis uses one dedicated `agentops:{preview}:v1:ledger` key. Atomic mutation includes tasks, reservations and audit together, avoiding cross-key partial writes. Initial limits: 32 tasks, 100 events/task and 1 MB ledger. Capacity exhaustion fails closed; no records are silently trimmed or deleted. This is a deliberate small Phase 1 implementation of the proposed storage model; per-task/index migration is future reviewed work, not necessary for the one-task pilot.
- SQLite is strictly a disposable local verification adapter, with actual transactions/WAL and reconnect/process tests. Never use it as Vercel durable storage. CI runs the same store with the actual Redis Lua transaction in an ephemeral localhost Redis service; it has no application secrets and does no deletes.
- `api/agent-operations.js` + `lib/agent-operations-api.js`: default-off Preview gate, current internal admin checks, client impersonation denial, same-origin mutations, fail-closed rate limit, bounded input, no tenant selectors, separate worker credential, immutable scope and separate one-use paid approval gate. Red operations are absent from the command API. No key, secret, approval or model selector from page text/model output is executable authority.
- `lib/agent-operations-worker.js`: each stage claims/reserves/executes/persists, fresh independent reviewer stage, abort monitoring, deadline, heartbeat and mode checks. Model output does not schedule itself. Mock path automatically executes the same persisted workflow, explicitly synthetic.
- `scripts/agent-operations-worker.cjs`: standalone bounded process, max eight scheduling cycles, ten minutes, no browser/chat lifetime dependency, no recurring scheduler. Mock mode by default; real Responses adapter requires both trusted server approval and local paid gate/key. Local external-process verification uses a separate credential-free script.
- Pilot uses fixed supported Responses API transport instead of adding SDK dependencies. Managed Agents/eve remain evaluated alternatives, not installed runtimes. Role-specific instructions and validated outputs implement manager-owned delegation with deterministic orchestration; this is not remote control of Work chats.
- Capture tool restricts all browser requests to GET on the exact pinned origin, blocks API routes/other origins/service workers/WebSockets, uses an empty cookie context and no production credentials. Capture locations and viewports are code-defined, not model-supplied. Secrets are excluded from browser environment and bypass headers only target the pinned Preview. Arbitrary shell, source edits and external writes do not exist in its toolset.
- Admin Agent Operations view shows persisted task status, stages, usage/reservations/unknown attempts, events, review/artifact metadata, directory, refresh and mock queue/cancel. No decorative Start/Approve/Release controls. External output is inserted with textContent. Visible-view polling reads only; worker execution is independent.

## Verification scope

Focused behavioral tests exercise real SQLite persistence/reconnect and parallel claims, idempotency conflicts, four-stage delegation, rejected QA/rework termination, active cancellation/abort, stale fencing, interrupted/unknown recovery, task/call/deadline/audit bounds, daily/monthly reservations, uncertain storage writes, auth revocation, internal versus impersonated admin, CSRF, worker permissions, paid gate/one-use approval, fixed model/request limits, cost validation, secret-pattern redaction and a complete mocked Responses transport.

Local browser harness renders the real admin HTML/new UI with real API and SQLite, but MOCK authentication/models and unrelated dashboard scripts removed. It verifies create → persisted mock worker stages → verified report, cancel, escaped output, disabled state and layouts at 1440/768/390/320. This is not full authenticated hosted dashboard acceptance. Private local screenshots/report are in ignored `artifacts/agent-operations/browser/`.

No live OpenAI model request, paid pilot, scheduled worker, public phone/resource exposure, live billing, active database restore or Production deployment is authorized by these tests. Cloud Agent Operations environment flags remain unset unless explicitly recorded later. Sensitive Preview Redis credentials are present in the existing Vercel project but cannot be retrieved by the connector; no broad credentials were copied into a worker. API account/model access and secure worker injection remain launch configuration gates.

## Operational limits

Uncertain paid executions are blocked, not silently replayed; recovery is conservative and may need manual provider-side reconciliation. Cancellation cannot undo already consumed tokens. The ledger permanently consumes worst-case reservations for the initial pilot; there is no refund loop. Initial capacity is intentionally small. UTC day/month accounting is internal and separate from displayed local times. Secret redaction covers known patterns, not arbitrary confidential input: do not submit customer/private transcripts. Browser output paths are local artifact names, not a publicly accessible artifact service. No source-patch or integration permission has been added.
