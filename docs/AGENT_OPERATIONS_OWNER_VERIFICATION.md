# Preview Owner Verification

The authenticated admin dashboard's Agent Operations view now contains an inert Owner Verification panel. It reuses the existing session, member, workspace owner, same-origin POST, rate limit and lifecycle service. Every action remains server-authorized. No new credential, role, public endpoint or operational permission is introduced.

The server advertises the panel only when the current workspace owner is verified, VERCEL_ENV is preview, paid execution is explicitly false, the approved finite verification window is valid (at most two hours), and the current release lock passes. Non-owner admins and restricted workers receive no availability. Production is rejected before authentication. Loading the view performs only reads.

The fixed eleven scenarios invoke the actual tracked Node controller and shared lifecycle/CAS implementation using isolated owner/nonce/slot records: success, prepare-lost, activate-lost, initialize-lost, cancel, revoked, renew-failure, expired, redis-unavailable, timeout and cleanup-failure. Test definitions are authorized=false, maxCalls=0 and maxMicros=0. They never create operational tasks, grants, spending reservations or provider requests. Fault scenarios are isolated adapter/controller seams, not an actual cloud Redis outage.

Run one scenario with a fresh record, then inspect its controller result and separate authoritative cleanup readback. The latter requires the exact record ID, current deployment/source/release, zero limits, revoked status and zero lease. A failed scenario remains failed even if cleanup is confirmed. Cancellation aborts the original request, attempts central revocation and checks the original immutable nonce/slot; failures remain visibly unconfirmed. No automatic reruns. Download preserves the visible metadata history. Record input allows owner-selected cross-deployment readbacks without exporting session credentials.

The panel does not activate the verification window or paid execution. Only an explicitly authorized Preview configuration pass may set the existing finite inert window. Remove it afterward and deploy a disabled replacement; old immutable deployments retain their finite inert window until expiry, with all created test records centrally revoked. Already transmitted provider requests cannot be recalled; no such request is available to this panel.

Independent QA and Auditor caught a misleading cleanup-readback possibility in the initial UI. Permanent executed-UI regressions now reject mismatched records, source/release, nonzero limits and live leases. Backend authorization was not bypassed. Both independent reviews accepted the corrected source. Hosted results must be recorded separately after publication; offline results alone do not establish hosted readiness.
