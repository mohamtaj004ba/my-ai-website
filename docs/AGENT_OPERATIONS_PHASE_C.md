# Phase C — bounded read-only engineering tools

## Scope and authority

Extend the existing owner/workspace Redis CAS journal, department catalog and guarded operations API. No competing controller or authorization system. Levels1/2 expose a fixed client-dashboard deployed-source profile and deterministic evidence-linked proposals. Level3 records an inert workspace contract with no checkout or changes. Levels4/5 disabled; Production prohibited. No paid provider dispatch, credentials, shell, general filesystem, network, customer APIs, Git push or deployment executor is added.

## Actual tool path

Owner dashboard preset → exact existing operations-create → server-selected roles/templates/dependencies → existing run claim/fence/lease → fresh owner authorization → locked curated source reads → backend canonical result check → final fenced CAS → persisted proposals, separate evidence-review results and consolidated references. Cancellation/emergency use the existing controls. The original paid execution/approval/spending ledger stays read-only.

Allowed source is exactly dashboard.html, dashboard.js, dashboard.css and package.json from the deployed application. Regular-file/realpath containment, explicit literal packaging paths, UTF8/binary/byte limits, recognizable-secret screening and a reviewed source manifest bind actual bytes. Unknown paths, private configs, fixtures, credentials and arbitrary URLs cannot be requested. Screening is not a proof that every possible secret is detectable; the curated files must remain public source. Preview evidence is the authenticated broker's own exact runtime/source/release identity, not a remote availability probe. Connected Work applications are not inherited by internal API agents. GitHub branch diffs, remote CI, live Vercel status, browser capture/geometry and sanitized runtime-log adapters remain unavailable until separately scoped service integration exists.

## Investigation and proposal semantics

The Chief routing substitute delegates four stages: engineering-inspect (Dashboard), engineering-propose (Backend/Integration), engineering-review (Independent QA role with separate backend verification only), engineering-draft (disabled descriptor). Each dependent stage requires exactly one prior engineering stage, checked at admission. Dependencies are disclosed in the server directory and validated in the UI before saving an uncertain-delivery journal. Evidence receipts bind owner/workspace, task/plan, execution/fence, source/release, manifest hash, dependencies, excerpt hashes and observation time. Downstream results are canonically checked against immutable predecessor reports.

Three current source observations are precise and qualified: dashboard.js line958 native confirmation for note deletion (design preference, not proven defect); line521 refresh cadence/editing pause (observed behavior); line7 explicitly deferred booking (documented limitation). They generate problem/component, impact uncertainty, source evidence, reproduction, corrective approach, benefit, dependencies, permissions, verification and owner-approval requirements. They are not three manufactured bugs. Reasoning is deterministic and no model intelligence or visual inspection is inferred.

The review preserves each proposal as unresolved pending independently authorized rendered/runtime review. Structural/integrity checks are not substantive acceptance or human independence. Owner identity cannot attest its own independence. Business acceptance remains not-granted and acceptedWorkfalse. The deterministic Chief final report preserves each original proposal, exact review decision/reason/evidence, uncertainty and authority status, with separate task/result references. The owner can open its dedicated report.

## Isolated preparation foundation

The inert draft descriptor binds exact source, repository and approved feature branch, three allowable UI files,200KB/three-file/ten-minute bounds, no network/shell/credentials/customer data, zero changes and disabled apply/commit/push/deploy. Future code preparation requires an approved isolated executor, resource enforcement, independently trusted reviewer identity, verified preimages, explicit owner permission and discard/cleanup proof.

## Threat and failure model

Prevent source/path traversal, symlink/Windows alias/encoded paths, source drift, credentials in context, forged role/tool grants, cross-workspace access, stale release/task/fence, duplicate claims, cancellation races, rehashed substituted evidence, forged acceptance and write-enabled drafts. Fail closed on unavailable storage/source, preserve sanitized ENG codes, never retry automatically. Original evidence/accounting and unresolved uncertainty remain unchanged. Cancellation reserves and journal capacity limits from PhaseB remain authoritative.

Independent review caught and corrected separate-read source hash ambiguity, ambiguous predecessor admission, downstream provenance substitution and incorrect implementation-role labeling. QA caught incomplete UI selection being journaled as a rejected payload; prerequisites are now checked before saving/sending, without bypassing server validation.

## Build efficiency

Prior PhaseB documentation-only pushes created READY deployments despite no application change; no CPU-dollar amount was available. A narrow Preview-feature ignored-build step compares exact HEAD to Vercel's previous successful branch SHA, requires ancestry and regular files, and skips only allowlisted handoff/Phase docs/engineering-plan changes. Missing history/context, runtime/config/dependency/test changes and Production always build. No CI, release identity, protection or security check is skipped. Actual hosted skip must be verified on a later documentation checkpoint before claiming measured avoided builds.
