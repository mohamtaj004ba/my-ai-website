# Phase C.3 unified integration foundation

## Actual scope
Extends the existing workspace-owner API, department/task registry, Redis CAS journal and immutable audit chain. No separate task system, credentials or spending ledger. Nine provider definitions cover GitHub, Vercel, Gmail, Calendar, Drive/Docs/Sheets, Contacts, Stripe, OpenAI Platform and dedicated browser. Capability definitions carry classification/level and operational versus unverified future status. Provider OAuth scopes are distinguished from internal policy requirements. Only fixed public GitHub workflow metadata is executable; curated deployed source and trusted disposable draft remain existing tools.

## Owner flow and authority
Connections & Permissions appears in the existing authenticated Agent Operations panel. The owner can record provider prerequisites, revoke local access, explicitly restore only fixed public GitHub reads, and assign one bounded read to an exact persisted engineering task. Role/department/source/release/origin/revision/fence are backend-derived. Single-use admission and bounded calls/rate/concurrency are committed before transport; all consequential boundaries revalidate task and permission. Replay returns the existing receipt without dispatch. Connection implies no automatic specialist rights. Levels4–6, private tools, paid calls, external mutations, credential administration and publication stay disabled. Chief coordination cannot change backend acceptance or reviewer authority.

Existing engineering-inspect routes its public CI GET through the same policy module, with original task attempt/fence/lease/concurrency controls and unchanged evidence contract. Manual gateway reads use grant/admission/receipt records in that same journal; they do not mark a task completed. Public provider data is untrusted, projected to bounded known workflow/status fields, without raw logs, headers, titles or arbitrary URLs.

## Revocation and safe recovery
Owner/provider or grant revocation is local CallerCore denial, not provider OAuth-token revocation. No private token exists. Explicit local revocation works when the unrelated paid ledger is unavailable, provided owner policy and operations Redis remain authoritative. Redis failures deny execution. Emergency Stop revokes integration grants including those on completed plans. Pending read interruption preserves receipt and revokes its grant; no automatic retry. If a controller terminates after admission, use owner revoke (or revoke-grant), then a fresh explicitly scoped grant; an expired pending receipt never authorizes automatic redispatch. A transmitted public GET cannot be recalled.

## Credentials and external prerequisites
No ChatGPT-connected token, browser cookie, developer CLI credential or model key is copied into the gateway. No token entry/issuance/storage API exists. Private connectors remain unconfigured until separately registered provider applications, owner consent, resource allowlists and approved managed encrypted credential storage/key management are genuinely available. Prefer approved managed token brokering; store only opaque connection identifiers locally and use short-lived credentials server-side. No homegrown plaintext vault or fabricated OAuth redirect. Exact provider actions/scopes and official sources are in AGENT_OPERATIONS_PHASE_C3_REQUIREMENTS.md. Setup buttons record missing prerequisites; they do not launch a working OAuth flow.

## Dedicated browser boundary
A separate capture module supports fixed desktop/mobile public Preview scopes, sanitized diagnostic types, geometry/rendered text, screenshot hashes, bounded operations, cancellation and verified cleanup. It cannot run through the gateway today. Playwright1.55.0 is installed but Chromium executable is absent; dedicated runtime, transport authentication, verified network-egress isolation, process watchdog and scoped protected-Preview identity are missing. Browser routes/DNS checks do not prove OS isolation. No Work browser access is inherited. Tests use explicit synthetic browser responses, not real captures. See AGENT_OPERATIONS_BROWSER_SERVICE.md. No new provider/account/subscription is provisioned.

## Adding a provider
Add an immutable registered capability/classification definition, official authentication/scope requirements, a fixed-resource trusted read adapter, sanitized output contract and adversarial tests. Obtain separate approved provider application/consent and managed-vault reference. Add server-bound role/task policies with default denial, source/resource/tenant identity checks, expiry/rate/budget limits, durable admission/revocation/audit, and independent review. Only then expose an owner control and verify hosted success/denial before reporting operational status. Mutation capabilities require a separate exact owner-action contract and remain disabled in this phase.
