# Authenticated owner Pilot Control

The supported entry is the existing authenticated admin dashboard → Agent Operations → Owner Pilot Control. Direct navigation to an API URL is not an execution prerequisite. CallerCore session, internal admin membership, current workspace ownership, same-origin POST and Preview-only guards apply server-side. Vercel Deployment Protection stays enabled. No new credentials or authorization system exist.

Start sends only a selection binding: approval ID, workflow ID, full approval digest, release digest, application source and deployment origin. The server compares all six against the specific configured, unexpired approval before calling the existing `supervisePilot`. The digest binds all approved fields, including expiration, scope, models and limits. It does not grant permission. The dashboard cannot issue approvals, activate arbitrary grants, select a model, raise budgets or bypass preflight. The Redis ledger remains authoritative for one-use initialization, leases, dispatch, reservations and independent acceptance. `canStart` means a configured approval is eligible for activation, whereas `paidExecution` reports currently active dispatch authority; these must not be conflated.

Cancel and Emergency Stop centrally revoke owned approval IDs through the existing CAS ledger before aborting the response stream. This includes an exact configured pre-task tombstone and historical owned approvals on disabled replacement deployments. Revocation retires grants and nonterminal workflows without releasing uncertain holds. An owner session lost during cleanup is shown as unconfirmed; no automatic retry or restart occurs. A duplicate Start cannot duplicate authority, but concurrent controller cleanup may conservatively cancel the first run. Explicit committed revocation blocks subsequent boundaries immediately; disappearance without revocation retains the documented maximum30-second lease fallback. In-flight provider requests cannot be recalled.

Status reads central owner-filtered records, authoritative budget and immutable task outcomes; no capabilities, owner hash or revocation token are projected. A failed status request clears eligibility and does not claim successful cleanup. UI refresh never resumes execution. Server-only Production rejection remains independent of hidden controls.
