# Proposed draft-data preparation v3

Extends the existing disposable draft parent and restricted trusted child. Original v1 fixed-comment and v2 reviewed fixed-correction contracts remain supported. No parallel authorization, journal, credential service, route or publication system is introduced.

The new `prepareProposal` interface requires an exact original `engineering-text-proposal-v1`, source commit, existing task/execution/fence/owner/workspace/runtime binding and trusted before/after authorization callback. The existing guarded operations gateway must supply that callback and independently fence final persistence. A caller-created proposal or role is not authority. Pure `validateProposalArtifact` requires the original proposal and binding, recomputes exact bytes/hashes and rejects substituted task or patch data.

Only curated `dashboard.js` can be copied. One to three ordered, nonoverlapping replacements require unique original before-text, its computed preimage hash, the locked full-file hash and exact original offsets. Replacement text is limited to 2 KB per side, 12 KB total edit data, one file and 700 KB resulting source. Invalid paths, overlapping/reordered edits, stale source and extra command/options are denied. Offset metadata is deterministically derived from source; it is not silently repaired model output.

The same tracked child receives empty environment, restricted temporary-directory writes, explicit trusted-module reads, 64 MB V8 old-space and ten-second maximum duration. It applies text operations only. It does not import, evaluate or execute proposed JavaScript, invoke caller commands, contact external services, publish, commit, push or deploy. Patch bytes, before/after hashes, original proposal and task binding persist after normal destruction. Cancellation/timeout reject only after the active child terminates and cleanup completes. Source hashes are rechecked against the authoritative repository.

This is a data-only draft workspace, not an untrusted-code sandbox or proof of OS network/total-memory isolation. Parent hard termination may leave copied public source; crash-orphan sweeping remains unverified. No real correction is applied to the repository. Trusted semantic review, owner approval, actual corrective tests and separately authorized publishing remain additional gates. Offline child tests prove data preparation and isolation boundaries, not model judgment or live operational permission.
