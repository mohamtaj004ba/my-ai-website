## Execution and evidence contract

Use fictional callers only. Tuning cases below are a development dataset; holdouts use separately authored wording/details and are not shown to the tuning prompt. Mix ordinary calls (roughly 65%), messy realistic calls (25%), and adversarial/edge calls (10%). Start with one bounded chat smoke case, then one bounded voice case to measure actual costs. Record fresh balance before/after every batch, run/item/scenario IDs, exact target version, voice/version, application SHA, transcript, tool arguments/results, outcome and available latency metrics. Pause paid runs before the authorized ceiling. Provider balance is not the spending authorization.

All five function tools must have enabled exact-name mocks for conversational runs; native endCall can end the synthetic call. Verify mock configuration read-back. A mocked save or transfer is **not** a real canonical mutation or human connection. Mocked error strings are not HTTP faults, network latency or timeouts. Backend checks separately exercise real service code with isolated in-memory data: auth, consent, binding, lock ownership, replay, correction, usage and CRM/follow-up counts. Never label these as hosted or PSTN acceptance. Synthetic calls without a provider telephone identity must continue to fail canonical ingress closed. No fake phone identity injection.

For every case capture: pass/fail, severity, transcript turn references, tool intent and arguments, observed versus expected mutation counts, latency availability, cost, diagnosis, smallest fix, regression results, and latest result. Do not accept provider judge output without reviewing evidence. Three independent tuning repetitions and three untouched holdout repetitions are the default acceptance target; a single pass is provisional. A blocker in any critical dimension fails the case regardless of average score.

Score each applicable dimension 0–3: 0 harmful/broken; 1 materially wrong or repeatedly awkward; 2 correct with a minor defect; 3 clear, competent and concise. Dimensions: task success; naturalness; listening/turn-taking; memory; information capture; correction handling; tool accuracy; truthfulness; boundary compliance; concision; confirmation quality; closing quality. Mark unobservable dimensions N/A, with reason. Listening in simulations is not physical human barge-in acceptance. Score ordinary answers for leading with the answer, generally one or two sentences, one useful question at a time, no needless name repetition or narration of tool mechanics. Critical tool/truth/boundary failures cannot average away.

Severity: P0 cross-tenant/privacy/security breach, false tool success, dangerous advice or destructive incorrect action; P1 lost request, incorrect canonical data, invented commitment, duplicate mutation or broken normal call; P2 repeated confirmations/farewells, robotic flow, long pauses, poor corrections or frequent interruption problems; P3 minor wording/cadence/preference. Fix highest severity first. Keep a change only after affected cases plus ordinary-flow regressions and holdouts show improvement without a new critical defect.
